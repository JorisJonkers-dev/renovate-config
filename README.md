# renovate-config

Shared Renovate preset for JorisJonkers-dev repositories.

## What It Is

`renovate-config` provides the default Renovate policy for org repositories:
semantic commits, dependency dashboards, pinned ranges, grouped first-party
updates, deploy-v2 source pin handling, and guardrails for migration-era
coordinates.

## Use

```json
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "extends": ["github>JorisJonkers-dev/renovate-config"]
}
```

## GitHub Packages Is Not Readable By Renovate

First-party artifacts — `@jorisjonkers-dev/*` npm packages and `dev.jorisjonkers`
maven coordinates — publish only to GitHub Packages, and the hosted Renovate app
has no token for it. Two consequences, both observed:

- Every lookup for those packages returns `no-result`, which the dependency
  dashboard reports as a warning on each repository.
- In a pnpm repository the lockfile cannot be regenerated either, because `pnpm`
  cannot resolve the private packages it already contains. Renovate then raises
  a dependency PR with `package.json` edited and `pnpm-lock.yaml` untouched, and
  every install job fails with `ERR_PNPM_OUTDATED_LOCKFILE`. This hit
  `agents-ui#92` and `agents-ui#96`, each of which needed the lockfile
  regenerated by hand before it could merge.

Maven coordinates work around it with custom managers that follow the source
repositories' release tags. npm lookups are disabled outright, because the same
trick would still leave the lockfile stale: a `custom.regex` update to
`package.json` does not run the npm artifact updater. First-party npm bumps are
therefore done by hand when a client is released.

**The fix needs a credential this repository cannot hold.** Mint a PAT with
`read:packages`, encrypt it at <https://app.renovatebot.com/encrypt> for the
`JorisJonkers-dev` organization, and add:

```json
"hostRules": [
  {
    "hostType": "npm",
    "matchHost": "npm.pkg.github.com",
    "encrypted": { "token": "<encrypted-value>" }
  }
]
```

With that in place, drop the two `enabled: false` rules and the maven custom
managers: lookups resolve, lockfiles regenerate, and first-party bumps arrive
like any other dependency.

## Local Validation

```bash
python3 -m json.tool default.json >/dev/null
npx --yes --package renovate renovate-config-validator default.json renovate.json
```
